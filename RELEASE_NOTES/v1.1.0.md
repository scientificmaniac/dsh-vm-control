# dsh-vm-control v1.1.0 · 第一个正式发行版

DeepSeek Harness 的 VMware 虚拟机管理插件。电源、快照、实时资源占用、网络配置与 VMX 参数一处管完，并能把虚拟机的 SSH 接入一键导入 `dsh-ssh-vault`。

> `v1.0.0` 是仓库初次上传时的标签，没有发行包；**本版是第一个正式发行版**，包含 1.0.0 的全部内容加上下方的 SSH 联动与发行工程。

## 新增 / Added

### 与 dsh-ssh-vault 的联动

- 虚拟机卡片新增「SSH 导入」：预填别名、地址（取自 VMware Tools 报告的客户机 IP）、端口、账号与认证方式，确认后写入 `dsh-ssh-vault`。
- `vm_config action=ssh` 为模型提供同一份建议与入口说明；保险库的密文只认对方自己的密钥，因此写入必须由用户在设置页确认。
- 导入口令只出现在提交给 `dsh-ssh-vault` 的那一次请求里；本插件不落盘、不写日志、不回读保险库。
- 对方未安装 / 未认证 / 出错三种情况分别提示，缺席时仍可复制 SSH 命令，其它功能不受影响。
- 别名规范化与非 ASCII 处理；同批虚拟机撞名时按 vmx 路径码点顺序自动加 `-2`，跨平台可复现。

### 发行工程

- `npm run release`：一致性检查 → 语法检查 → 测试 → 打包 → 产物校验，一次跑完，任一步失败即中止。
- `npm run pack:dist`：跳过测试直接出包（离线出包用）；`npm run check`：只做一致性检查。
- GitHub Actions：`tests` 在两个平台 × 两个 Node 版本上跑测试；`release` 在 tag 推送时用同一份产物创建发行版并上传 `.tgz` 与 `SHA256SUMS.txt`。

## 安装 / Install

```bash
# 从 npm（若已发布）
dsh plugin --profile desktop install dsh-vm-control@1.1.0

# 或用本发行版附带的包
dsh plugin --profile desktop install ./dsh-vm-control-1.1.0.tgz
```

安装后**重启 DSH**。要求 Node ≥ 20，以及 VMware Workstation / Player / Fusion 提供的 `vmrun`。

## 升级说明 / Upgrade

- 从 1.0.0 升级无需迁移：`vms.json` 格式未变，插件数据目录（默认 `%DSH_HOME%/vm-control`）原样沿用。
- 新增的导入口受 `permissions.config` 控制；把它设为 `false` 即禁用导入，其余功能不变。
- 检查包完整性：`sha256sum -c SHA256SUMS.txt`（Windows：`certutil -hashfile dsh-vm-control-1.1.0.tgz SHA256`）。

## 已知限制

- 通过 VMware 界面暂停的虚拟机会显示为「运行中」——没有可查的命令行状态位。
- macOS / Linux 只采集 CPU 与 RSS，没有 IO 细分与线程数。
- 改写 VMX 只能在关机状态下进行（挂起状态允许，但会提示）。
- 只管理本机 VMware 产品；ESXi / vCenter 不在范围内。

# English

A VMware Workstation / Player / Fusion control plugin for the DeepSeek Harness: power, snapshots, live resource use, network layout, VMX parameters — plus one-step import of a VM's SSH access into `dsh-ssh-vault`.

`v1.0.0` was the initial upload tag and shipped no artifact; **this is the first formal release** and contains everything from 1.0.0 plus the SSH integration and release tooling below.

## Added

- **dsh-ssh-vault import**: the VM card gains an "SSH import" panel that prefills alias, host (guest IP from VMware Tools), port, user and auth, then writes into the vault on confirm. `vm_config action=ssh` returns the same proposal to the model; the vault ciphertext only answers to the sibling's key, so the write is confirmed by a human.
- The password exists only in the single request to `dsh-ssh-vault`; this plugin never stores, logs or reads it back.
- Distinct handling for missing / unauthenticated / failing sibling, with a copyable SSH command when it is absent — nothing else is locked.
- Deterministic alias normalisation with a `-2` suffix on collisions (ordered by vmx path codepoints).
- **Release tooling**: `npm run release` runs consistency → syntax → tests → pack → artifact verification; `release.yml` turns a tag push into a GitHub Release with the `.tgz` and `SHA256SUMS.txt` attached; `tests.yml` runs the suite on Windows and Linux across Node 20 and 22.

## Install

```bash
dsh plugin --profile desktop install dsh-vm-control@1.1.0
# or use the attached package
dsh plugin --profile desktop install ./dsh-vm-control-1.1.0.tgz
```

Restart DSH afterwards. Node ≥ 20 and a `vmrun` from VMware Workstation / Player / Fusion are required.

## Notes

- Upgrading from 1.0.0 needs no migration: `vms.json` is unchanged and the data directory is reused.
- The import follows `permissions.config`; setting it to `false` disables only that path.
- Verified before packaging: 53 unit + 19 API + 5 client smoke + 5 integration (against dsh-ssh-vault 2.3.0's real source) + 8 read-only live tests on VMware Workstation 17.6, plus an artifact content check.
